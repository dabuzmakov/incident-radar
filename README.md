# Incident Radar

Incident Radar — консольная утилита на C# для анализа NGINX-логов. Читает локальные файлы, файлы по glob-маске и логи по HTTP/HTTPS, разбирает записи и собирает статистику за выбранный период.

Формирует отчёт в JSON или Markdown: выводит его в stdout или сохраняет в файл. Отчёт включает статистику запросов, названия HTTP-статусов и список использованных протоколов.

## Структура проекта

```text
src/
├── IncidentRadar.App/
│   ├── Analysis/            # обработка записей и фильтрация по датам
│   │   └── Statistics/      # подсчёт статистики и модель результата
│   ├── CLI/                 # разбор аргументов и отдельная проверка настроек
│   ├── Exceptions/          # ошибки источников и выходного файла
│   ├── Extensions/          # вспомогательные методы для HTTP-методов
│   ├── Logging/             # вывод предупреждений и ошибок в stderr
│   ├── Parsing/             # парсер строк, его интерфейс и модели записей
│   ├── Properties/          # профиль запуска для отладки
│   ├── Reports/             # построение отчётов, подготовка пути и сохранение
│   ├── Sources/
│   │   ├── Resolving/       # преобразование пути, маски или URL в список источников
│   │   ├── Opening/         # открытие файлов и HTTP-потоков, выбор способа открытия
│   │   └── Reading/         # построчное чтение открытых источников
│   ├── UI/                  # консольный вывод и подтверждение перезаписи
│   ├── AppComposer.cs       # создание и соединение компонентов приложения
│   └── Program.cs           # запуск анализа и обработка ошибок
└── IncidentRadar.Tests/
    └── Mandatory/
        ├── Mr1/            # тесты CLI и источников логов
        ├── Mr2/            # тесты парсера, фильтра дат и статистики
        └── Mr3/            # тесты отчётов, защиты от перезаписи и кодов возврата
samples/
└── logs/                   # примеры логов и ожидаемая статистика
```

`LogAnalyzer` получает компоненты через конструктор: поиск источников, чтение, парсер, логгер и фабрику сборщика статистики. Для каждого анализа создаётся отдельный сборщик, поэтому результаты предыдущего запуска не накапливаются. Стандартные реализации собираются в `AppComposer`.

## Запуск анализа

Нужен **.NET SDK 10**. Команды выполняются из корня проекта.

Анализ одного файла:

```bash
dotnet run --project src/IncidentRadar.App -- --path samples/logs/access-2025-03-01.log --output-format markdown
```

Аргументы `--path` и `--output-format` обязательны.

| Аргумент | Назначение |
|---|---|
| `--path`, `-p` | Путь к файлу, glob-маска или URL |
| `--output-format`, `-f` | Формат отчёта: `json` или `markdown` |
| `--output-path`, `-o` | Необязательный путь к отчёту: `.json` для JSON, `.md` для Markdown |
| `--from` | Начальная дата в формате `yyyy-MM-dd` |
| `--to` | Конечная дата в формате `yyyy-MM-dd` |

Без `--output-path` отчёт выводится в stdout. Для сохранения укажите путь к файлу в существующей директории. Если файл уже существует, приложение запросит подтверждение: `y` разрешает перезапись, другой ответ или конец ввода отменяет сохранение. Относительные пути отсчитываются от рабочей папки процесса.

Анализ нескольких файлов с фильтром по датам:

```bash
dotnet run --project src/IncidentRadar.App -- --path "samples/logs/access-*.log" --output-format json --output-path report.json --from 2025-03-01 --to 2025-03-02
```

Маску нужно передавать в кавычках, чтобы её обработала сама программа. Для локальных файлов поддерживаются расширения `.log` и `.txt`. В `--path` также можно передать URL по HTTP/HTTPS.

## Файлы при отладке и в тестах

Профиль `IncidentRadar.App` в `Properties/launchSettings.json` запускает анализ из `samples/logs` с маской `access-2025-03-0*.log` и форматом `json`.

Для тестов папка `samples` копируется в каталог сборки. Тесты находят её через `AppContext.BaseDirectory`. Исходные примеры редактируются в корневой `samples/logs`, после чего тестовый проект нужно пересобрать.

## Обработка логов

Файлы и HTTP-ответы читаются построчно, без загрузки всего лога в память.

Из каждой корректной строки извлекаются IP-адрес, пользователь, дата и время, HTTP-метод, ресурс, протокол, код ответа, размер ответа, Referer и User-Agent. Метод, ресурс и протокол хранятся отдельно. Некорректные строки пропускаются с сообщением в stderr, после чего анализ продолжается.

Границы периода включаются в выборку. Можно указать только `--from`, только `--to` или обе даты. Без фильтра обрабатываются все корректные записи. Для сравнения используется календарная дата из записи лога без перевода в UTC.

## Статистика

По записям, прошедшим фильтр, считаются:

- общее количество запросов;
- использованные протоколы;
- количество ответов с каждым HTTP-кодом и его название;
- топ-10 ресурсов по количеству запросов;
- средний и максимальный размер ответа в байтах;
- p95 размера ответа.

Ресурсы сортируются по количеству запросов по убыванию. При равном количестве — по имени ресурса.

Для p95 выбран метод **nearest rank**: размеры ответов упорядочиваются по возрастанию, затем берётся значение на позиции `ceil(0.95 × N)`, где `N` — число запросов, а позиции считаются с единицы.

Если запросов нет, средний размер, максимум и p95 равны нулю. Для расчёта хранятся частоты ресурсов, кодов и размеров ответов, поэтому расход памяти зависит от количества уникальных значений.

## Форматы отчётов

Оба формата содержат список и количество источников, число прочитанных и некорректных строк, количество запросов, размеры ответов, топ ресурсов, HTTP-статусы и протоколы.

Пример JSON для одного запроса:

```json
{
  "files": ["access.log"],
  "filesCount": 1,
  "processedLinesCount": 1,
  "malformedLinesCount": 0,
  "totalRequestsCount": 1,
  "responseSizeInBytes": { "average": 100, "max": 100, "p95": 100 },
  "resources": [{ "resource": "/health", "count": 1 }],
  "responseCodes": [{ "code": 200, "name": "OK", "count": 1 }],
  "protocols": ["HTTP/1.1"]
}
```

В Markdown сводка и размеры представлены списками, а ресурсы и статусы — таблицами. Фрагмент отчёта:

```markdown
## Response size in bytes
- Average: 100.00
- Max: 100
- P95: 100

## Response codes
| Code | Name | Count |
| --- | --- | ---: |
| 200 | OK | 1 |
```

## Коды завершения

| Код | Значение |
|---|---|
| `0` | Успешное выполнение |
| `1` | Непредвиденная внутренняя ошибка |
| `2` | Некорректные аргументы, недоступный вход или отказ от перезаписи |

Предупреждения о некорректных строках и сообщения об ошибках выводятся в stderr.
