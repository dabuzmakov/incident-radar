# Incident Radar

Incident Radar — консольная утилита на C# для анализа NGINX-логов. Читает локальные файлы, файлы по glob-маске и логи по HTTP/HTTPS, разбирает записи и собирает статистику за выбранный период.

На этапе MR1–MR2 реализованы чтение, разбор строк, фильтрация по датам и подсчёт статистики. Формирование и сохранение отчётов в JSON и Markdown будут добавлены в MR3. Сейчас результат анализа не выводится в консоль и не сохраняется в файл.

## Структура проекта

```text
src/
├── IncidentRadar.App/
│   ├── Analysis/           # фильтрация записей и сбор статистики
│   ├── CLI/                # разбор и проверка аргументов запуска
│   ├── Exceptions/         # ошибки источников логов
│   ├── Extensions/         # вспомогательные методы для HTTP-методов
│   ├── Parsing/            # парсер строк и модели записей
│   ├── Sources/            # поиск источников и потоковое чтение
│   └── Program.cs          # запуск анализа и обработка ошибок
└── IncidentRadar.Tests/
    └── Mandatory/
        ├── Mr1/            # тесты CLI и источников логов
        ├── Mr2/            # тесты парсера, фильтра дат и статистики
        └── Mr3/            # заготовки тестов отчётов и кодов возврата
samples/
└── logs/                   # примеры логов и ожидаемая статистика
```

## Запуск анализа

Нужен **.NET SDK 10**. Команды выполняются из корня проекта.

Анализ одного файла:

```bash
dotnet run --project src/IncidentRadar.App -- --path samples/logs/access-2025-03-01.log --output-format markdown
```

Аргументы `--path` и `--output-format` обязательны.

| Аргумент | Назначение |
|---|---|
| `--path`, `-p` | Путь к файлу, glob-маска или URL |
| `--output-format`, `-f` | Формат будущего отчёта: `json` или `markdown` |
| `--output-path`, `-o` | Необязательный путь к будущему отчёту: `.json` для JSON, `.md` для Markdown |
| `--from` | Начальная дата в формате `yyyy-MM-dd` |
| `--to` | Конечная дата в формате `yyyy-MM-dd` |

Параметры отчёта уже проверяются, но сам отчёт пока не создаётся.

Анализ нескольких файлов с фильтром по датам:

```bash
dotnet run --project src/IncidentRadar.App -- --path "samples/logs/access-*.log" --output-format json --from 2025-03-01 --to 2025-03-02
```

Маску нужно передавать в кавычках, чтобы её обработала сама программа. Для локальных файлов поддерживаются расширения `.log` и `.txt`.

## Обработка логов

Файлы и HTTP-ответы читаются построчно, без загрузки всего лога в память.

Из каждой корректной строки извлекаются IP-адрес, пользователь, дата и время, HTTP-метод, ресурс, протокол, код ответа, размер ответа, Referer и User-Agent. Метод, ресурс и протокол хранятся отдельно. Некорректные строки пропускаются с сообщением в stderr, после чего анализ продолжается.

Границы периода включаются в выборку. Можно указать только `--from`, только `--to` или обе даты. Без фильтра обрабатываются все корректные записи. Для сравнения используется календарная дата из записи лога без перевода в UTC.

## Статистика

По записям, прошедшим фильтр, считаются:

- общее количество запросов;
- количество ответов с каждым HTTP-кодом;
- топ-10 ресурсов по количеству запросов;
- средний и максимальный размер ответа в байтах;
- p95 размера ответа.

Ресурсы сортируются по количеству запросов по убыванию. При равном количестве — по имени ресурса.

Для p95 выбран метод **nearest rank**: размеры ответов упорядочиваются по возрастанию, затем берётся значение на позиции `ceil(0.95 × N)`, где `N` — число запросов, а позиции считаются с единицы.

Если запросов нет, средний размер, максимум и p95 равны нулю. Для расчёта хранятся частоты ресурсов, кодов и размеров ответов, поэтому расход памяти зависит от количества уникальных значений.
